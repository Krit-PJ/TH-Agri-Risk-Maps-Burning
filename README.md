# Agri-Risk Map Burning (V3)

ระบบประเมินและเฝ้าระวังความเสี่ยงการเผาในพื้นที่เกษตร — ขยายจากต้นแบบจังหวัดกำแพงเพชรเป็นระดับประเทศ
ผู้ใช้ทั่วไปเลือกจังหวัดที่มีข้อมูลจุดความร้อน (HS) จากแผนที่ประเทศไทย แล้วระบบเปิดแผนที่ความเสี่ยง Dashboard และรายงานพิมพ์ของจังหวัดนั้น

* บัญชีเริ่มต้น (Admin จังหวัดกำแพงเพชร และ Super Admin) กำหนดในไฟล์ `Secrets.gs` ที่มีเฉพาะในโครงการ Apps Script ไม่อยู่ใน GitHub (ดู `backend/Secrets.example.gs`)
* ผู้ที่ยังไม่มีสิทธิ์กด **เข้าสู่ระบบ → Admin → ขออนุญาตใช้งาน** คำขอจะไปที่ Admin ของจังหวัดนั้นและ Super Admin
* เบอร์โทรเก็บในชีตแบบข้อความ (Format `@`) และระบบเติมเลข `0` นำหน้าที่หายไปให้อัตโนมัติ ทั้งตอนอ่านและเขียน
* รหัสผ่าน Super Admin เก็บเป็นค่า Hash ใน Script Properties ไม่อยู่ในชีตหรือโค้ดหน้าเว็บ เปลี่ยนได้โดยเรียก `setSuperAdmin('ชื่อใหม่', 'รหัสใหม่')` จาก Apps Script Editor
* เข้าสู่ระบบด้วยเบอร์โทรได้ทันทีโดยไม่จำกัดจำนวนครั้ง ระบบบันทึก **ทุกการพยายามเข้าใช้** ในชีต `LoginAttempts` (เวลา, หมายเลข/ชื่อผู้ใช้, ผล, ชื่อ, จังหวัด, อุปกรณ์ — ไม่บันทึกรหัสผ่าน)
* แท็บ **รายงานการเข้าใช้** ในแผงผู้ดูแล: Admin เห็นการเข้าใช้ของจังหวัดตน, Super Admin เห็นทั้งหมดพร้อมรายชื่อ **หมายเลขที่ไม่มีในระบบแต่พยายามเข้าใช้** (จำนวนครั้ง ครั้งแรก ล่าสุด) และปุ่ม "เพิ่มเป็นผู้ดูแล"
* ระบบตรวจสถานะบัญชีทุกคำสั่ง (ระงับสิทธิ์มีผลทันที) และบันทึกประวัติทุกการเปลี่ยนแปลง

## ติดตั้ง Backend (ครั้งแรก)

ฐานข้อมูลสร้างไว้แล้วในโฟลเดอร์ Drive ของโครงการ: **TH Agri-Risk Map Burning V3 - Database**

1. เปิด Google Sheet ฐานข้อมูล → **ส่วนขยาย → Apps Script**
2. วางเนื้อหา `backend/Code.gs` แทนโค้ดเดิม เพิ่มไฟล์ `Risk.gs` และ `Units.gs` (สร้างไฟล์ชื่อเดียวกันใน Apps Script) เพิ่มไฟล์ `Secrets.gs` ตามแบบ `backend/Secrets.example.gs` และ (ตัวเลือก) วาง `backend/appsscript.json`
3. (ไม่บังคับ) เลือกฟังก์ชัน `setup` → **เรียกใช้** — ถ้าไม่เรียก ระบบจะติดตั้งให้อัตโนมัติเมื่อมีการเรียก API ครั้งแรก (สร้างชีต Accounts, Requests, ProvinceSummary, Batches, Counter, Settings, AuditLog, LoginAttempts และบัญชีเริ่มต้น)
4. **ทำให้ใช้งานได้ → การทำให้ใช้งานได้รายการใหม่ → เว็บแอป**
   * ดำเนินการในฐานะ: **ฉัน** · ผู้ที่มีสิทธิ์เข้าถึง: **ทุกคน**
5. คัดลอก URL ที่ลงท้าย `/exec` ไปใส่ใน `js/config.js`
   ```js
   API_URL: 'https://script.google.com/macros/s/xxxxxxxx/exec',
   ```
6. เมื่อแก้ `Code.gs` ภายหลัง ให้ **จัดการการทำให้ใช้งานได้ → แก้ไข → เวอร์ชันใหม่** (URL เดิมใช้ต่อได้)

ข้อมูล HS แต่ละจังหวัดเก็บในชีต `HS_<รหัสจังหวัด>` เช่น `HS_62` (เพิ่มอัตโนมัติเมื่อนำเข้า)

## การนำเข้าข้อมูล HS

แผงผู้ดูแลระบบ → **นำเข้า HS** → เลือกไฟล์ → ระบบตรวจสอบให้อัตโนมัติ → **บันทึก**

* **Admin**: ระบบผูกการนำเข้ากับจังหวัดตามสิทธิ์อัตโนมัติ ไฟล์ที่มีหลายจังหวัดจะนำเข้าเฉพาะแถวของจังหวัดตน และแจ้งจำนวนแถวที่ข้าม
* **Super Admin**: ระบบอ่านคอลัมน์ Province แล้วแสดงรายการจังหวัดในไฟล์พร้อมจำนวนจุด เลือกนำเข้า 1 จังหวัด หลายจังหวัด หรือ "เลือกทุกจังหวัด" ระบบตรวจสอบและตรวจยอด hsPlant แยกรายจังหวัด จังหวัดที่ไม่ผ่านจะถูกข้าม ส่วนที่ผ่านบันทึกต่อเนื่องเป็นชุดข้อมูลแยกรายจังหวัด

* คอลัมน์ที่ต้องมี: `hsID`, `Date` หรือ `YYYY-MM-DD`, `Province`, `LandType`, `PlantType` และพิกัด `Maps` (ลิงก์ Google Maps) หรือ `X`/`Y` (UTM 47/48) หรือ `Latitude`/`Longitude`
* ใช้ได้เพิ่มเติม: `Time`, `Amphoe`, `Tambon`, `BaanN`
* เกณฑ์คัดกรองตามต้นแบบ: Province = จังหวัดที่เลือก → LandType = พื้นที่เกษตร → PlantType ∈ นาข้าว, อ้อย, ข้าวโพดและไร่หมุนเวียน, เกษตรอื่น ๆ, อื่น ๆ → ตัด hsID ซ้ำ
* หากไฟล์มีชีต `hsPlant…` ระบบตรวจยอดรายชนิดพืชของจังหวัด ยอดไม่ตรงจะไม่ให้บันทึก
* อำเภอ/ตำบลผูกจากชื่อในตารางก่อน หากไม่พบจึงใช้ตำแหน่งพิกัด
* นำเข้าซ้ำได้อย่างปลอดภัย จุดที่มี hsID เดิมจะไม่ถูกบันทึกซ้ำ ลบเป็นรายชุดได้ที่แท็บ **ชุดข้อมูล**

## แบบจำลองความเสี่ยง: Burning Risk Index (BRI) — v3.5

คำนวณที่ Backend (`backend/Risk.gs`) จากทุกจังหวัดที่มีข้อมูล เพื่อให้ระดับเทียบข้ามจังหวัดได้ หน้าเว็บรับเฉพาะผลระดับ

```
BRI = 0.60·D + 0.20·P + 0.20·C
D = ความหนาแน่น HS ต่อพื้นที่ (ถ่วงฤดู 0.40/0.35/0.25 ใหม่→เก่า) ปรับด้วย Empirical Bayes แล้วเทียบเปอร์เซ็นไทล์กับฤดูอ้างอิง
P = การเกิดซ้ำ: สัดส่วนฤดูที่พบ HS (จาก 3 ฤดู) · C = คะแนนชนิดพืชของจุด HS (45→0, 90→100)
```

* ทุกฤดูใช้**ช่วงวันเดียวกัน** (1 ต.ค. → วันสิ้นสุดของช่วงที่เลือก) ก่อน 30 พ.ย. ใช้ฤดูที่ครบล่าสุด เพราะต้นฤดูข้อมูลยังน้อย (ทดสอบแล้วความน่าเชื่อถือ ρ 0.64 ณ 1 พ.ย. → 0.81 ณ 30 พ.ย.)
* 4 ระดับ: จุดตัด = เปอร์เซ็นไทล์ 50/75/90 ของ BRI ในฤดูอ้างอิง (ค่าเริ่มต้น 2567,2568 — ตั้งค่าได้) ตรึงไว้ ระดับจึงลดลงได้จริงเมื่อการเผาลดลงทั้งภูมิภาค
* **ประชาชน**เห็นเฉพาะ 4 สีและจำนวนจุดในช่วงที่เลือก · **ผู้ดูแล (ในขอบเขตสิทธิ์)** เห็นคะแนน BRI, D/P/C และลูกศรแนวโน้มเทียบค่าฐาน
* ผลทดสอบทำนายฤดูถัดไป (ข้อมูล FIRMS 2566–2569): อำเภอ ρ 0.94–0.95, AUC 0.97–0.98 เทียบสูตรเดิม (Model A) ρ 0.53–0.56
* วงกลมกลุ่มจุดบนแผนที่ใช้สีกลาง ตัวเลข = จำนวนจุดความร้อนในกลุ่ม และสีจุด HS รายฤดูเป็นโทนน้ำเงิน/ม่วง ไม่ซ้ำกับสีระดับความเสี่ยง
* Dashboard เทียบ "ช่วงเดียวกันปีก่อน" แบบรายวัน (ตัดที่วันล่าสุดของข้อมูล)

## แหล่งข้อมูล HS (ต้นสังกัด / NASA FIRMS)

* ทุกจุดมีคอลัมน์ `source` (`AGENCY` = หน่วยงานต้นสังกัด, `FIRMS` = NASA FIRMS) และ `satellite` — ข้อมูลเดิมถูกระบุเป็น `AGENCY` อัตโนมัติเมื่อติดตั้ง v3.4
* Super Admin / Mini Super Admin เลือก **แหล่งข้อมูลหลัก** ที่แท็บ *ตั้งค่าระบบ* แผนที่ Dashboard รายงาน และ BRI ใช้แหล่งเดียวทุกปี (ไม่ผสมข้ามปี)
* แท็บ *เปรียบเทียบแหล่งข้อมูล*: จำนวนรายเดือน/รายอำเภอของทั้งสองแหล่ง และอัตราจุดที่ตรงกัน (วันเดียวกัน ≤ 1 กม.)
* ไฟล์ที่มีคอลัมน์ `Source = FIRMS` บันทึกเป็นแหล่ง NASA FIRMS (นำเข้าได้เฉพาะผู้ดูแลระดับประเทศ)
* ชุด FIRMS สร้างจาก VIIRS Suomi-NPP + NOAA-20 (ตัดจุดซ้ำ ≤ 1 กม. ≤ 2 ชม.) จำแนกพื้นที่เกษตรด้วย ESA WorldCover 2021 + ข้อมูลต้นสังกัดเดิมเป็นตัวอย่างสอน (ทดสอบ AUC 0.987)

คำอธิบายสัญลักษณ์อยู่ใต้แผนที่ ไม่มีแถบคะแนนหรือกล่องใดทับข้อมูลบนแผนที่ ตารางย่อขนาดอัตโนมัติให้พอดี 1 หน้า
