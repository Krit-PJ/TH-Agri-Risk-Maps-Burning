# Agri-Risk Map Burning (V3)

ระบบประเมินและเฝ้าระวังความเสี่ยงการเผาในพื้นที่เกษตร — ขยายจากต้นแบบจังหวัดกำแพงเพชรเป็นระดับประเทศ
ผู้ใช้ทั่วไปเลือกจังหวัดที่มีข้อมูลจุดความร้อน (HS) จากแผนที่ประเทศไทย แล้วระบบเปิดแผนที่ความเสี่ยง Dashboard และรายงานพิมพ์ของจังหวัดนั้น

| Super Admin | ชื่อผู้ใช้ + รหัสผ่าน | ทั้งระบบ | สิทธิ์เต็ม รวมถึงแต่งตั้ง/ปรับ/ระงับ/ลบ Mini Super Admin (เลือก "บทบาท" ในแท็บผู้ดูแลระบบ) |

* บัญชีเริ่มต้น (Admin จังหวัดกำแพงเพชร และ Super Admin) กำหนดในไฟล์ `Secrets.gs` ที่มีเฉพาะในโครงการ Apps Script ไม่อยู่ใน GitHub (ดู `backend/Secrets.example.gs`)
* ผู้ที่ยังไม่มีสิทธิ์กด **เข้าสู่ระบบ → Admin → ขออนุญาตใช้งาน** คำขอจะไปที่ Admin ของจังหวัดนั้นและ Super Admin
* เบอร์โทรเก็บในชีตแบบข้อความ (Format `@`) และระบบเติมเลข `0` นำหน้าที่หายไปให้อัตโนมัติ ทั้งตอนอ่านและเขียน
* รหัสผ่าน Super Admin เก็บเป็นค่า Hash ใน Script Properties ไม่อยู่ในชีตหรือโค้ดหน้าเว็บ เปลี่ยนได้โดยเรียก `setSuperAdmin('ชื่อใหม่', 'รหัสใหม่')` จาก Apps Script Editor
* เข้าสู่ระบบด้วยเบอร์โทรได้ทันทีโดยไม่จำกัดจำนวนครั้ง ระบบบันทึก **ทุกการพยายามเข้าใช้** ในชีต `LoginAttempts` (เวลา, หมายเลข/ชื่อผู้ใช้, ผล, ชื่อ, จังหวัด, อุปกรณ์ — ไม่บันทึกรหัสผ่าน)
* แท็บ **รายงานการเข้าใช้** ในแผงผู้ดูแล: Admin เห็นการเข้าใช้ของจังหวัดตน, Super Admin เห็นทั้งหมดพร้อมรายชื่อ **หมายเลขที่ไม่มีในระบบแต่พยายามเข้าใช้** (จำนวนครั้ง ครั้งแรก ล่าสุด) และปุ่ม "เพิ่มเป็นผู้ดูแล"
* ระบบตรวจสถานะบัญชีทุกคำสั่ง (ระงับสิทธิ์มีผลทันที) และบันทึกประวัติทุกการเปลี่ยนแปลง

## ติดตั้ง Backend (ครั้งแรก)

ฐานข้อมูลสร้างไว้แล้วในโฟลเดอร์ Drive ของโครงการ: **TH Agri-Risk Map Burning V3 - Database**

1. เปิด Google Sheet ฐานข้อมูล → **ส่วนขยาย → Apps Script**
2. วางเนื้อหา `backend/Code.gs` แทนโค้ดเดิม เพิ่มไฟล์ `Risk.gs` และ `Units.gs` (สร้างไฟล์ชื่อเดียวกันใน Apps Script) เพิ่มไฟล์ `Secrets.gs` ตามแบบ `backend/Secrets.example.gs` และ (ตัวเลือก) วาง `backend/appsscript.json`
3. (ไม่บังคับ) เลือกฟังก์ชัน `setup` → **เรียกใช้** — ถ้าไม่เรียก ระบบจะติดตั้งให้อัตโนมัติเมื่อมีการเรียก API ครั้งแรก (สร้างชีต Accounts, Requests, ProvinceSummary, Batches, Counter, Settings, AuditLog, LoginAttempts และบัญชีเริ่มต้น)
4. **ทำให้ใช้งานได้ → การทำให้ใช้งานได้รายการใหม่ → เว็บแอป**
   * ดำเนินการในฐานะ: **ฉัน** · ผู้ที่มีสิทธิ์เข้าถึง: **ทุกคน**
5. คัดลอก URL ที่ลงท้าย `/exec` ไปใส่ใน `js/config.js`
   ```js
   API_URL: 'https://script.google.com/macros/s/xxxxxxxx/exec',
   ```
6. เมื่อแก้ `Code.gs` ภายหลัง ให้ **จัดการการทำให้ใช้งานได้ → แก้ไข → เวอร์ชันใหม่** (URL เดิมใช้ต่อได้)

ข้อมูล HS แต่ละจังหวัดเก็บในชีต `HS_<รหัสจังหวัด>` เช่น `HS_62` (เพิ่มอัตโนมัติเมื่อนำเข้า)

## การนำเข้าข้อมูล HS

แผงผู้ดูแลระบบ → **นำเข้า HS** → เลือกไฟล์ → (ไม่บังคับ) ช่วงวันที่ / โหมด upsert → **ตรวจสอบไฟล์** → **บันทึกเข้าฐานข้อมูล** + ยืนยัน

* **Admin**: ผูกการนำเข้ากับจังหวัดตามสิทธิ์อัตโนมัติ · **Super Admin / Mini Super Admin**: เลือก 1 จังหวัด หลายจังหวัด หรือทุกจังหวัดจากคอลัมน์ Province
* คอลัมน์ที่ต้องมี: `hsID`, `Date` หรือ `YYYY-MM-DD`, `Province`, `LandType`, `PlantType` และพิกัด `Maps` หรือ `X`/`Y` (UTM 47/48) หรือ `Latitude`/`Longitude` · เพิ่มเติม: `Time`, `Amphoe`, `Tambon`, `BaanN`
* นำเข้า **ทุก LandType** (พื้นที่เกษตร, เขต สปก., ป่าอนุรักษ์, ป่าสงวนแห่งชาติ, ชุมชนและอื่น ๆ, พื้นที่ริมทางหลวง) และ PlantType รวม `พื้นที่ป่า`
* **ช่วงวันที่**: นำเข้าเฉพาะบางช่วงของไฟล์ได้ · **upsert**: จุดที่มี hsID อยู่แล้วจะถูกปรับปรุงและย้ายเข้าชุดใหม่ (ค่าเริ่มต้น = ข้าม)
* ตรวจยอดก่อนบันทึกกับชีต `Land…` (รายประเภทพื้นที่) และ `hsPlant…` (รายชนิดพืช พื้นที่เกษตร) เมื่อนำเข้าทั้งไฟล์ · ตรวจยอดหลังบันทึกกับฐานข้อมูลจริงทุกครั้ง แล้วคำนวณระดับความเสี่ยงล่วงหน้า
* วันที่ Excel อ่านเป็นเลขลำดับวัน (ไม่ขึ้นกับเขตเวลา) — แก้ปัญหาวันที่เลื่อน 1 วันในเบราว์เซอร์เขตเวลาไทย
* แท็บ **ชุดข้อมูล**: เปิด/ปิดการใช้งานรายชุดหรือหลายชุด (ปิด = เก็บไว้แต่ไม่แสดง/ไม่ประเมิน) แสดงจำนวนจุดคงเหลือจริง ลบได้รายชุด · ก่อนปิดระบบแจ้งจังหวัด/จำนวนจุด/ช่วงวันที่ที่จะหายไป (v3.9.1)
* **v3.9.1**: ชุดข้อมูลที่นำเข้าหรือปรับปรุง (รวมการนำเข้าเพิ่มเข้าชุดเดิมที่เคยปิด) **เปิดใช้งานอัตโนมัติ** (`hsImport_` ตั้ง `active = TRUE` ทุกครั้ง) · ถ้าแก้คอลัมน์ `active` ในชีต `Batches` โดยตรง ให้รัน `refreshAllSummaries` จาก Editor เพื่อปรับยอดสรุปและเดือนที่มีข้อมูล

## ABRI-2Y v1.0 (ค่าเริ่มต้นตั้งแต่ v3.9)

`backend/Abri.gs` — ระดับความเสี่ยงการเผาเชิงประวัติ (Historical Hotspot Risk) เพื่อกำหนดพื้นที่เป้าหมายส่งเสริมการลดเผา **ไม่ใช่การทำนาย**

```
ปีที่ประเมิน Y = ปีงบถัดจากปีงบล่าสุดที่ครบแล้ว ณ วันสิ้นสุดช่วงที่เลือก · ปีฐาน = Y−2, Y−1 (ตรึงตลอดปีงบ Y)
N2Y   = HS(Y−2) + HS(Y−1)     ประเภทพื้นที่ที่เลือก (ค่าเริ่มต้นพื้นที่เกษตร) ไม่นับ PlantType = พื้นที่ป่า ในพื้นที่เกษตร/เขต สปก.
ABRI  = เปอร์เซ็นไทล์แบบลำดับกลางของ N2Y เทียบหน่วยในจังหวัดเดียวกันที่มี N2Y ≥ 3 (ตำบลและอำเภอจัดลำดับแยกกัน)
ระดับ = ≥90 สูงมาก · ≥75 สูง · ≥50 ปานกลาง · <50 ต่ำ · N2Y < 3 = ต่ำ
ปีงบ Y = เฝ้าระวังเท่านั้น (hs0) ไม่คิดคะแนน · ข้อมูลประกอบ: ชนิดพืชหลัก, ความหนาแน่นต่อพื้นที่เกษตร
```

* สถานะ **Provisional**: ยังไม่มีพื้นที่ปลูกรายพืชรายปี — เมื่อได้ข้อมูล ทบก. (`Province, Amphoe, Tambon, CropType, FiscalYear, AgriculturalAreaRai`) จะพัฒนาเป็น Area-Normalized / Empirical Bayes
* ผลปีงบ 2570 (ฐาน 2568–2569 พื้นที่เกษตร): 1,546 ตำบล สูงมาก 70 · สูง 109 · ปานกลาง 166 · ต่ำ 1,201
* สูตรที่เลือกได้ (setting `risk_model`, ครั้งละ 1 สูตร): `ABRI` (ค่าเริ่มต้น) · `M5` · `M4` — นำ Model 3 (BRI v2) และ Model 1 (ต้นแบบ) ออกใน v3.9

## Model 5 (ทางเลือก): ความหนาแน่นต่อพื้นที่เกษตร + การเผาซ้ำ รายจังหวัด

`backend/Model5.gs` — ใช้ข้อมูลที่เกิดขึ้นแล้วบ่งชี้ระดับความเสี่ยง **ไม่ใช่การทำนาย** และใช้ข้อมูลของจังหวัดนั้นประเมินจังหวัดนั้นเท่านั้น

```
ปีฐาน   = ปีงบของวันสิ้นสุดช่วงที่เลือก + ย้อนหลัง ≤ 2 ปีที่มีข้อมูล · ใช้เฉพาะเดือนที่มีข้อมูลครบทุกปีฐาน (ปัจจุบัน ม.ค.–พ.ค.)
D_i     = จุดเฉลี่ยต่อปี ÷ (พื้นที่เพาะปลูก ESA WorldCover/1,000 ไร่)        R_i = % จุดในกริด 1 กม. ที่พบจุด ≥ 2 ปีฐาน
คะแนน  = 0.7·P(D) + 0.3·P(R)  (เปอร์เซ็นไทล์ในจังหวัด เฉพาะตำบลที่มีจุดรวม ≥ 3)
ระดับ   = ลำดับเปอร์เซ็นไทล์ของคะแนน ≥90 สูงมาก · ≥75 สูง · ≥50 ปานกลาง · ต่ำ · จุดรวม < 3 = ต่ำ · ไม่มีพื้นที่เกษตร = ไม่ประเมิน
อำเภอ   = รวมจุด/พื้นที่ทั้งอำเภอ แล้วจัดลำดับเทียบอำเภอในจังหวัด + จำนวนตำบลระดับสูง–สูงมาก
ข้อมูลประกอบ (ไม่คิดคะแนน): แนวโน้มปีล่าสุดเทียบค่าเฉลี่ยปีก่อน · ชนิดพืช
```

### ช่วงเวลาและการเทียบปีก่อน (หน้าเว็บ)
* ค่าเริ่มต้น = **ปีงบประมาณล่าสุดที่ครบแล้ว** · เลือกปีงบ (รายการ “ปีงบประมาณ”) หรือกำหนดเดือนเองได้
* จุดความร้อน **ทุกจุดในช่วงที่เลือก** อยู่ชั้นบนสุดของแผนที่ (pane `hsCur`, v3.9.1 — เดิมแสดงเฉพาะปีงบล่าสุด) · ช่วงเดียวกันปีก่อนแสดงเป็นชั้นสีเทา (pane `hsPrev`)
* รายการปี พ.ศ. ของช่วงข้อมูลเรียงจากปีล่าสุดลงไป (v3.9.1)
* ตาราง **เปรียบเทียบ HS**: ช่วงเดียวกันปีก่อน → ช่วงที่เลือก → เพิ่ม/ลด · “ช่วงที่เลือก” = จำนวนจริงทั้งหมด (ผลรวม = การ์ดสรุป มีแถว “ไม่ระบุพื้นที่” ถ้ามี) · ปีก่อนไม่มีข้อมูล → “ไม่มีข้อมูล” และ % = – · ปีก่อนมีบางเดือน → ปีก่อนและ % คิดเฉพาะเดือนที่มีข้อมูลทั้งสองปี (หัวตาราง * + หมายเหตุ; v3.9.2 ไม่แสดงตัวเลข “เทียบ n” ซ้อนในช่วงที่เลือกแล้ว) · คลิกแถวเพื่อเจาะลงตำบล/เลือกตำบล
* `Geo.compareWindow` (ผ่าน `MapModule.compareInfo()`) ใช้ร่วมกันทุกส่วน: วันต่อวันเมื่อปีก่อนมีข้อมูลครบ · ถ้าไม่ครบ เทียบเฉพาะเดือนที่มีข้อมูลทั้งสองปี และแจ้งช่วงที่มีข้อมูล

## Model 4 (ทางเลือก, v3.7): คะแนนจัดลำดับพื้นที่เฝ้าระวังการเผาเกษตร

`backend/Model4.gs` · ค่าฐานกลางและพื้นที่เพาะปลูกใน `backend/Geo.gs` (สร้างอัตโนมัติ ห้ามแก้ด้วยมือ)

```
H_i   = EB( Σ_s w_s·N_i,s ÷ (A_i/1,000) )      หน่วยตรวจพบต่อ 1,000 ไร่เกษตรต่อฤดู
N_i,s = กริด 500 ม.–วัน ที่พบจุดความร้อนเกษตร (NASA FIRMS VIIRS Suomi-NPP ดวงเดียว) ฤดูที่ครบแล้ว ≤ 3 ฤดู (0.40/0.35/0.25)
A_i   = พื้นที่เพาะปลูก ESA WorldCover 2021 (ไร่)   ·   EB ใช้ μ, s² กลางที่ตรึงไว้
คะแนน = เปอร์เซ็นไทล์ของ H เทียบฐานกลาง 17 จังหวัด ฤดู 2567–2568 (เวอร์ชัน M4-2569.1) · ระดับ <50 / 50–75 / 75–90 / ≥90
อำเภอ = ค่าเฉลี่ยถ่วงพื้นที่เกษตร + จำนวนตำบลคะแนนสูง · ไม่มีพื้นที่เกษตร = ไม่ประเมิน (สีเทา)
```

* ทดสอบฤดู 2569 (เลือกด้วย 2567→2568): ตำบลคะแนนสูงสุด 10% ของพื้นที่เกษตรครอบคลุมหน่วยตรวจพบ 29.4% (baseline จำนวนจุด 23.0%, เกณฑ์รายจังหวัด 23.6%)
* ต้องเปิดใช้งานชุดข้อมูล NASA FIRMS (แหล่งข้อมูล FIRMS ไม่ถูกแสดงบนแผนที่เมื่อแหล่งหลักเป็นต้นสังกัด) และนำเข้า FIRMS Suomi-NPP เพิ่มหลังจบแต่ละฤดู
* ใช้กับพื้นที่เกษตร/เขต สปก. ของ 17 จังหวัดที่มีข้อมูลพื้นที่เพาะปลูก ประเภทอื่นใช้ ABRI-2Y อัตโนมัติ

## Public Data API v1.3

`GET …/exec?action=api&fn=meta|provinces|risk|hotspots|compare` (JSON หรือ `format=csv`) · **ข้อมูลชุดเดียวกับหน้าเว็บ** (ชุดที่เปิดใช้งาน · นโยบายดาวเทียม · สูตรที่ตั้งค่า · ช่วงเริ่มต้น = ปีงบล่าสุดที่ครบแล้ว) · `fn=compare` = ตารางเปรียบเทียบ HS เดียวกับการ์ดบนหน้าเว็บ (v1.3) · ค่าเริ่มต้น ABRI-2Y · `model=ABRI|M5|M4` — เอกสาร [`docs/API.md`](docs/API.md) · API key: `createApiKey('ชื่อ')` ใน Editor

## แหล่งข้อมูล HS (ต้นสังกัด / NASA FIRMS)

* ทุกจุดมีคอลัมน์ `source`, `satellite` และ `landType` (v3.5) · จุด FIRMS ใช้วันที่/เวลาไทยจากเวลา UTC ใน hsID
* ทุกจุดมีคอลัมน์ `source` (`AGENCY` = หน่วยงานต้นสังกัด, `FIRMS` = NASA FIRMS) และ `satellite` — ข้อมูลเดิมถูกระบุเป็น `AGENCY` อัตโนมัติเมื่อติดตั้ง v3.4
* Super Admin / Mini Super Admin เลือก **แหล่งข้อมูลหลัก** ที่แท็บ *ตั้งค่าระบบ* แผนที่ Dashboard รายงาน และการประเมินความเสี่ยงใช้แหล่งเดียวทุกปี (ไม่ผสมข้ามปี)
* แท็บ *เปรียบเทียบแหล่งข้อมูล*: จำนวนรายเดือน/รายอำเภอของทั้งสองแหล่ง และอัตราจุดที่ตรงกัน (วันเดียวกัน ≤ 1 กม.)
* ไฟล์ที่มีคอลัมน์ `Source = FIRMS` บันทึกเป็นแหล่ง NASA FIRMS (นำเข้าได้เฉพาะผู้ดูแลระดับประเทศ)
* ชุด FIRMS สร้างจาก VIIRS Suomi-NPP + NOAA-20 (ตัดจุดซ้ำ ≤ 1 กม. ≤ 2 ชม.) จำแนกพื้นที่เกษตรด้วย ESA WorldCover 2021 + ข้อมูลต้นสังกัดเดิมเป็นตัวอย่างสอน (ทดสอบ AUC 0.987)
