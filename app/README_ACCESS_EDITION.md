# รุ่น 2 — บัญชีและขอบเขตพื้นที่ (21 ตุลาคม 2569)

## เปิดใช้งาน
ชุดนี้แยกจากโครงการเดิมใน `agri-risk-map-burning-v2-access` สำรองโฟลเดอร์สถานะเดิมก่อนอัปเดต แล้วใช้ Start.cmd ตามวิธีเดิม หรือรัน `node v2/server.cjs` ระบบต้องเปิดผ่านบริการ Node ไม่ใช่ดับเบิลคลิก index.html

หน้าทดสอบในเครื่องนี้: http://127.0.0.1:8770/ ใช้สถานะทดสอบแยกไว้ที่ `v2-access-preview-state` การทดสอบไม่ได้อนุมัติหรือรีเซ็ตบัญชีผู้ใช้จริง

## สิ่งที่มีและสิ่งที่ปรับ
โครงสร้างเดิมเป็น Dashboard แบบ Static + Node local service + JSON state + ตัวเชื่อม Google OAuth การเข้าสู่ระบบเดิมยังไม่มีทะเบียนคำขอและขอบเขตอำเภอ จึงเพิ่มการตรวจสิทธิ์ที่บริการเดิม พร้อมปิดช่องอ่านไฟล์ข้อมูลโดยตรง คงสูตรความเสี่ยงและ Dashboard เดิม และนำรหัสผ่านตัวอย่างออกจากคู่มือที่เปิดผ่านเว็บได้

- ผู้ใช้ทั่วไปเลือกจังหวัดก่อนแสดงข้อมูล เห็น HS เฉพาะจังหวัด/ปีที่ Super Admin อนุญาตเผยแพร่ ค่าเริ่มต้นยังไม่เผยแพร่ข้อมูล
- ลงทะเบียนผู้บันทึกหรือผู้สมัคร Admin แบบ pending พร้อมรุ่นประกาศ PDPA เวลารับทราบและเลขคำขอ กล่องรับทราบไม่ถูกเลือกไว้ล่วงหน้า
- Admin รายจังหวัดพิจารณาผู้บันทึกเฉพาะจังหวัดตน Super Admin พิจารณาได้ทั้งสองประเภทและมอบหมายพื้นที่
- บัญชี Admin เดิมที่ไม่มีจังหวัดจะเป็น assignment_required ให้ Super Admin กำหนดจังหวัดก่อนเข้าใช้งาน ไม่อนุมัติบัญชีจริงให้อัตโนมัติ
- Reset Password สำหรับบัญชีที่อนุมัติและอยู่ในสิทธิ์ แสดง Popup หลังสำเร็จ รหัสชั่วคราวตามที่เจ้าของกำหนด บังคับเปลี่ยนก่อนเข้าถึงข้อมูล พร้อมยกเลิก Session เดิม
- Header แสดงชื่อบัญชี ปุ่มเข้า/ออกระบบตรงสถานะ และมีลิงก์ตรวจสอบจุดความร้อนกับ Green Gain Hub เปิดแท็บใหม่
- Admin เข้า URL ตามจังหวัด เช่น `/kamphaengphet/` โดยสิทธิ์ยังยึดบัญชีฝั่งเซิร์ฟเวอร์ การเปลี่ยน URL ไม่เพิ่มสิทธิ์
- กรองแผนที่ ข้อมูล ส่งออก และนำเข้าจากขอบเขตเดียวกัน ป้องกันผลล่าช้าหลัง Logout แยกข้อมูลในหน่วยความจำตามหน้าที่เปิดอยู่ ไม่เก็บข้อมูลบัญชีลง Cache กลาง
- ขอบเขตโหลดรายจังหวัด แสดงทั้งประเทศเฉพาะขอบเขตจังหวัด Cache ขอบเขตสูงสุด 32 MiB แจ้งเมื่อข้อมูลขาด ไม่สร้างแนวเขตทดแทน

## การตั้งค่า
`config/access-policy.json` ระบุรุ่น/ไฟล์ประกาศ PDPA `docs/personal-data-notice.html` ตามข้อความที่เจ้าของให้ รุ่น 2026-10-21.1
นโยบายเผยแพร่ที่ปรับในหน้า Super Admin บันทึกใน `<state>/publication.json` จึงไม่ถูกแพ็กเกจใหม่เขียนทับ
บัญชี คำขอ และ Audit บันทึกใน `<state>/access-state.json` รักษา accounts.json เดิมเพื่อย้ายครั้งแรก ห้ามเผยแพร่ไฟล์สถานะหรือ config ที่มีบัญชีเริ่มต้นบน GitHub

เซิร์ฟเวอร์ใหม่จากโค้ดสาธารณะ: ตั้ง AGRI_STATE_DIR, AGRI_OWNER_USERNAME และ AGRI_OWNER_PASSWORD ผ่านระบบจัดการ Secret ของเครื่องแม่ข่าย แล้วรัน `node v2/bootstrap-owner.cjs` ก่อนเปิดบริการครั้งแรก สคริปต์ปฏิเสธหากมีสถานะบัญชีอยู่แล้ว ไม่ใช้เพื่อเขียนทับบัญชีเดิม

## Google และ GitHub
Apps Script เป็นตัวอ่าน **ชีตข้อมูลสาธารณะที่ตรวจแล้วเท่านั้น** ไม่ใช่ระบบบัญชีแทน Node ตั้ง Script Properties: SPREADSHEET_ID, PUBLIC_SHEET_NAME (ค่าเริ่มต้น PublicHS), PUBLIC_PROVINCE_CODES เช่น 62,50 ต้องมีคอลัมน์ provinceCode,districtCode,date,Latitude,Longitude,published โดยเผยแพร่เฉพาะแถว published=TRUE ตัวอย่างเรียก `?action=hotspots&provinceCode=62` ค่าเริ่มต้นปิดข้อมูลทั้งหมด
โค้ดทดสอบสถานะได้ด้วย `?action=health` ยังไม่มี Spreadsheet ID จริงที่เจ้าของระบุ จึงยังไม่ยืนยันการเชื่อมฐานข้อมูลจริง

GitHub Pages เปิดได้เฉพาะหน้าเว็บสาธารณะ บริการบัญชี/อนุมัติ/นำเข้าต้องใช้ Node บนเครื่องหรือแม่ข่าย HTTPS ที่มีพื้นที่เก็บสถานะถาวร GitHub Pages รัน Node Backend ไม่ได้ หน้าสาธารณะต้องไม่แสร้งให้ Login ผ่านการตรวจฝั่งเบราว์เซอร์

## ข้อจำกัดที่ต้องทราบ
- ยังไม่มีบริการแม่ข่าย HTTPS สำหรับบัญชีออนไลน์ที่เจ้าของระบุ รุ่นนี้ทดสอบการทำงานครบที่บริการในเครื่อง
- การตั้ง Google OAuth/URL ฐานข้อมูลกลางจำกัด Super Admin ตามข้อกำหนดสิทธิ์ใหม่ ยังไม่มีการผูก Google Source แยกรายจังหวัด
- ใช้ขอบเขตที่ติดตั้งบนเซิร์ฟเวอร์ใน data/boundary ปิดเมนูนำเข้าแผนที่ลง IndexedDB แบบเดิมเพื่อไม่ให้แทนที่ขอบเขตตามสิทธิ์ การอัปเดตชุดขอบเขตให้ผู้ดูแลติดตั้งไฟล์บนเซิร์ฟเวอร์ก่อน เมนูนำเข้า HS เดิมยังใช้ตามสิทธิ์
- มุมมองทั้งประเทศโหลดเฉพาะขอบเขตจังหวัด ต้องเลือกจังหวัดเพื่อคำนวณและพิมพ์รายงานรายละเอียด ส่วน API ส่งออก HS รองรับทุกจังหวัดตามสิทธิ์ Super Admin
- HS ที่ไม่มีรหัสอำเภอไม่อนุญาตให้ผู้บันทึกซึ่งจำกัดอำเภอนำเข้า ต้องสอบทานรหัสก่อน ไม่เดาจากชื่อหรือรหัสไปรษณีย์
- เก็บ Audit 10,000 รายการล่าสุด บัญชีและข้อมูลอยู่ใน JSON เหมาะกับบริการเครื่องเดียว การใช้งานพร้อมกันหลายเครื่องแม่ข่ายต้องมีฐานข้อมูลร่วมและ Audit ตามนโยบายหน่วยงาน
- ไม่มีการเพิ่มฟังก์ชันบันทึกผลตรวจภาคสนามใหม่ คงเฉพาะการจัดการและนำเข้าข้อมูลเดิมตามสิทธิ์
