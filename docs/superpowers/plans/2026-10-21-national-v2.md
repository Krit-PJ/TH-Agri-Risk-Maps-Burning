# Thailand Agri-Risk Maps Burning V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deploy a 77-province public risk map plus a secure Google Workspace registration/admin control plane.

**Architecture:** GitHub Pages serves only public map assets and reviewed snapshots. A Google Apps Script Web App owns registration, PDPA, authentication, authorization, provincial CRUD and publication into Google Sheets/Drive; no secret or phone allowlist is committed.

**Tech Stack:** HTML/CSS/vanilla JavaScript, Leaflet, Node.js tests, GeoJSON, GitHub Actions/Pages, Google Apps Script, Google Sheets and Drive.

**Spec:** `docs/superpowers/specs/2026-10-21-national-v2-design.md`

## Global Constraints

- Preserve `Risk = 0.40H + 0.20T + 0.20C + 0.20A` and existing aggregation/threshold behavior.
- Never fabricate Hotspot data or expose phone/account/credential data in GitHub.
- Use canonical source codes; boundaries are province/district/subdistrict only.
- Admin writes are restricted to its approved province; Super Admin spans all 77.
- Public province options are derived from actual published HS features.

## Review Focus

- Empty/malformed HS files must not activate a province or crash the map.
- A forged provinceCode in an Admin request must return forbidden before any Sheet mutation.
- Repeated registration with one idempotency key must create one request only.
- Public endpoints must never serialize phone hash, Google identity, role state or audit contents.
- Apps Script quota/lock contention must fail without partially publishing a snapshot.
